# 영창 Judge 이동 효과 결합 설계

> 작성일: 2026-07-30  
> 상태: 다음 후보 구현 전 확정 계약  
> 적용 범위: player `move`를 포함하는 영창의 판정·평가  
> 프로덕션 반영: 없음

## 문제 정의

현재 게임에서 영창 이동의 방향·거리·도착점을 플레이어가 정밀하게 제어하기 어렵다.
따라서 `move`는 독립적인 회피·거리 조절 수단보다 영창을 공간적으로 표현하는 안무에
가깝다. move-only 출력은 입력·판정 시간과 마나를 소비하면서도 안정적인 전투 효용을
제공하지 못할 수 있다.

후보 20~24에서는 이 문제를 해결하려고 모든 player move에 damage form을 강제했다.
그 결과 이동 영창의 전투 효용은 확보했지만, control·shield·buff·heal·summon이 더
자연스러운 입력까지 damage로 획일화하는 과잉 제약이 됐다.

## 핵심 계약

> player move는 단독 효용으로 사용하지 않는다. 이동 영창에는 의미상 자연스럽고
> 실제 효용이 있는 form을 하나 이상 결합하되, 그 effect는 damage로 고정하지 않는다.

- player move가 있는 `spell_plan`에는 실행 가능한 form이 최소 하나 있어야 한다.
- form effect는 `damage|control|shield|buff|heal|summon` 중 입력 의미에 맞게 고른다.
- move는 선택된 효과를 전달하거나 강조하는 안무여야 한다.
- form 수를 채우기 위해 입력과 무관한 효과·원소·투사체를 창작하지 않는다.
- player가 아닌 현상·형상·소환수의 이동은 form의 속도·궤적으로 표현하며
  player move를 만들지 않는다.
- 이동이 핵심이 아닌 치유·보호·강화·고정 제어에는 장식용 move를 추가하지 않는다.

## 효과 선택 우선순위

1. 입력에 명시된 효과와 결과를 보존한다.
2. 이동이 직접 만들어내는 결과를 고른다.
3. 직접 결과가 없으면 이동 목적과 이미지에 가장 가까운 전투 효용을 고른다.
4. 여러 해석이 자연스러우면 하나를 허용안으로 선택하되, damage를 기본값으로
   간주하지 않는다.

| 이동 의미 | 우선 고려 effect | 표현 예 |
|---|---|---|
| 돌진·관통·충돌·베기 | `damage` | 경로 참격, 접촉 피해, 착지 충격 |
| 휩쓸기·밀치기·빙결 흔적 | `control` 또는 `damage` | 넉백 wave, 감속 zone |
| 회피·탈출·은폐·안전 전이 | `shield` 또는 `buff` | 짧은 보호, 회피·기동 강화 |
| 답보·질주·비행·부유 | `damage|control|buff` | 발걸음 충격, 궤적 제어, 기동 강화 |
| 구조·구원·치유 대상으로 접근 | `heal` 또는 `shield` | 도착 지점 회복·보호 |
| 소환수 탑승·동행 | `summon` | 소환수 등장과 이동의 결합 |
| 공격 후 이탈 | `damage` 뒤 `move` | 참격 후 잔상과 함께 이탈 |

`heal`과 `summon`은 구조·구원·치유 대상·소환 주체가 입력에 드러날 때만 사용한다.

## 사건 관계

- 같은 순간 이동하며 효과 전달: 한 sequence의 `move + form`
- 이동한 뒤 도착 효과 발생: `move → form`
- 효과를 먼저 가한 뒤 이탈: `form → move`
- 이동 경로에 흔적을 남김: `move + wave|zone|slash`
- 발걸음마다 사건이 반복됨: 실제 반복 단계 또는 반복을 표현하는 form

병렬과 순차는 단계 수가 아니라 사건의 실제 시간 관계로 결정한다.

## 원소 선택

1. 입력에 명시된 원소를 최우선으로 사용한다.
2. 명시 원소가 없을 때만 이동 이미지의 안정적인 대응으로 추론한다.
   - 섬광·찰나·초고속: `light`
   - 공간 왜곡·사라짐·잔상: `dark`
   - 답보·비행·부유·질주: `wind`
   - 충돌·착지: `earth`
3. 같은 사건의 move와 form은 원칙적으로 같은 주원소를 공유한다.
4. 입력에 복합 원소가 실제로 있을 때만 다른 원소를 결합한다.
5. form effect를 추가하기 위해 별도의 원소를 창작하지 않는다.

## 시간 계약

후보 19에서 검증한 이동 의미별 목표시간을 유지한다.

| 의미 | 이동 단계 목표시간 |
|---|---:|
| 순간이동·점멸·찰나 | 80~200ms |
| 섬광·극고속 돌파 | 150~300ms |
| 대시·돌진·급습 | 250~550ms |
| 일반 이동·운송 | 500~900ms |
| 느린 보행·부유·순례 | 900~1600ms |

- 병렬 `move + form`은 같은 짧은 시간을 공유할 수 있다.
- 순차 사건은 이동 시간과 form 시간을 합산하고 `durationWeight`로 상대 비중을
  표현한다.
- effect 종류가 달라져도 이동 의미의 시간대는 바꾸지 않는다.

## 재판정 계약

재판정은 출력 구조가 실행 계약을 위반한 경우에만 한 번 수행한다.

재판정 대상:

- wait-only plan
- 의미 있는 입력의 잘못된 fizzle
- player move가 있으나 실행 가능한 form이 하나도 없는 plan
- 1인칭이 아닌 `X의 비행·낙하·도주`를 player move로 오해한 plan

재판정 대상이 아님:

- move와 form이 있지만 form effect가 기대와 다를 수 있는 경우
- damage 대신 control·shield·buff·heal·summon을 선택한 경우
- 여러 허용 해석 중 하나를 선택한 경우

effect 적합성은 재판정 강제가 아니라 기대값과 수동 시각 평가로 판단한다.

## 평가 기준

### 자동 하한선

- player move가 있는 plan에 실행 가능한 form이 존재하는가
- 필수 원소·형태·효과 목적이 보존됐는가
- 같은 사건의 move와 form 원소가 일관적인가
- 순차·병렬·반복·도착·이탈 관계가 보존됐는가
- 비플레이어 이동에 player move가 생기지 않았는가
- 비이동 영창에 장식용 move·damage가 생기지 않았는가

### 수동 평가

- form effect가 이동 이미지와 자연스럽게 연결되는가
- 이동 방향을 통제하지 못해도 실제 전투 효용이 남는가
- damage로 획일화되지 않았는가
- move가 핵심 효과를 방해하지 않고 장면을 강화하는가
- 속도·타격 위치·전환이 실제 화면에서 이해되는가

자동 점수는 최소 계약 훼손 감시용 하한선이며 시각적 만족도를 보증하지 않는다.

## 기존 실험 자료의 지위

- 후보 20~24는 “모든 move에 damage form 필수”라는 폐기된 전제를 검증한
  진단 실험으로 보존한다.
- `SEQUENCE_JUDGE_MOVEMENT_HELDOUT_EXPECTATIONS.json`도 같은 damage 강제 전제를
  포함하므로 다음 후보의 합격 기준이나 sealed 일반화 세트로 재사용하지 않는다.
- 기존 파일은 수정하지 않고 당시 실험의 재현 자료로 유지한다.
- 다음 후보 구현 전 이 문서 기준의 새 기대값 세트를 별도 파일로 작성하고 응답
  수집 전에 봉인한다.
