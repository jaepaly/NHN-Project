# 방 전투 프리셋 개편 설계

> 상태: 구현 전 설계안
>
> 담당: R1
>
> 관련: Issue #214, Issue #171
>
> 적용 시점: MapGraph 기반 방 진행 통합 이후 production 배선. 프리셋 데이터·선택기·DEV 계측은 선행 구현 가능.

## 1. 목적

Issue #214에서 R1 범위로 지정된 “방 전체 구조” 중 일반방·함정방·엘리트방의 전투 구성을 정의한다.

현재 런은 고정된 `waveSetId`를 순서대로 소비하며 다음 한계가 있다.

- 일반방 웨이브 구성이 고정 순번으로 반복된다.
- 함정방은 독립된 전투 구조 없이 기존 encounter에 저주만 중첩한다.
- 엘리트방은 고정된 1웨이브의 모든 적에게 modifier를 무작위 배정한다.
- 맵 진행도, 경로 위험도, 최근 프리셋 이력이 전투 구성에 반영되지 않는다.
- 프리셋별 실제 클리어 시간을 비교할 DEV 계측이 없다.

개편 후에는 검증된 일반 전투 프리셋을 공통 기반으로 사용하고, 방 종류에 따라 함정 또는 엘리트 규칙을 합성한다.

```text
일반방   = 기본 전투 프리셋
함정방   = 기본 전투 프리셋 + trapProfile
엘리트방 = 기본 전투 프리셋 + 프리셋 전용 elitePlan
```

보스방은 기존 전용 패턴을 유지한다. 보물방·제단방은 전투 프리셋을 소비하지 않는다.

## 2. 목표 런타임과 검증 기준

### 기준 플레이어

Tier 1은 런 보상을 획득하지 않은 기본 플레이어 상태를 기준점으로 측정한다. Tier 2·3은 실제 플레이어 성장에 적 스탯을 반응시키지 않고, 해당 진행 구간의 설계상 평균 성장을 재현한 고정 테스트 로드아웃으로 측정한다.

- Tier 1: 성장치 0인 기본 플레이어
- Tier 2: 런 중반의 대표 성장 상태
- Tier 3: 런 후반의 대표 성장 상태
- Tier 2·3을 성장치 0으로 실행하는 측정은 난이도 기울기 확인용 스트레스 테스트로 분리

대표 성장 로드아웃의 정확한 친화·각인·정령·각성 구성은 보상 곡선 통합 후 확정한다. `playerPowerIndex`는 측정 로그의 보조값으로만 사용하며 적 스탯·프리셋 선정·시연 난이도의 입력으로 사용하지 않는다.

### 방 종류별 목표

| 방 종류 | 활성 실제 시간 중심값 | 평균적 영창 플레이 | 비고 |
|---|---:|---:|---|
| 일반방 | 47초 | 약 3회 | 프리셋 자체의 기준 |
| 함정방 | 54초 | 3~4회 | 같은 프리셋에 함정 규칙 합성 |
| 엘리트방 | 60초 | 약 4회 | 같은 프리셋에 지정된 적만 승격 |
| 스테이지 보스 | 78초 | 약 5회 | 기존 전용 패턴 유지 |
| 최종 보스 | 90초 | 약 6회 | 기존 전용 패턴 유지 |

측정 구간은 첫 웨이브 생성부터 마지막 적 사망까지의 활성 실제 시간이다. 영창 입력·원격 판정·시퀀스 실행과 웨이브 사이 2초 게임 시간 대기는 포함하고, 명시적 일시정지·입장 페이드·보상 선택·포탈 이동은 제외한다.

각 프리셋이 중심값을 정확히 맞출 필요는 없다. 방 종류별 전체 표본의 중앙값을 핵심 지표로 사용하고, 개별 프리셋의 편차는 전투 다양성으로 허용한다. 영창 횟수는 합격 기준이 아니라 목표시간 이탈 원인을 해석하는 참고값이다.

성장한 플레이어가 후반 방을 더 빠르게 정리하는 것은 우선 성장 보상으로 허용한다. 통합 플레이테스트에서 후반 클리어 시간이 반복적으로 과도하게 짧을 때만 진행 구간별 전투 예산을 조정한다.

## 3. 전체 런 난이도 곡선

전투 티어는 스테이지마다 초기화하지 않고 전체 런 진행도를 세 구간으로 나눈다.

```text
런 초반 ───────── 런 중반 ───────── 런 후반
  Tier 1            Tier 2            Tier 3
```

MapGraph 통합 후 진행도는 최종 보스까지의 전역 진행 축을 사용한다.

```ts
progress = node.layer / finalBoss.layer;
```

기본 구간은 다음과 같다.

| 전체 런 진행도 | 기본 티어 |
|---:|---:|
| 0~33% | Tier 1 |
| 33~66% | Tier 2 |
| 66~100% | Tier 3 |

구간 경계와 경로 성격은 인접 티어 후보를 허용한다.

- low: 기본 티어 또는 한 단계 아래
- balanced: 기본 티어
- high: 기본 티어 또는 한 단계 위
- 결과는 Tier 1~3 범위로 제한

함정방과 엘리트방이라는 이유로 몬스터 티어를 추가 상승시키지 않는다. 함정 규칙과 엘리트 승격 자체가 방 종류의 추가 난도를 담당한다.

한 런 안에서는 플레이어 성장 기울기가 프리셋 난이도 상승보다 조금 높아야 한다. 후반방이 약간 빨라지는 것은 정상적인 성장 보상으로 허용한다.

난이도 담당은 다음처럼 분리한다.

```text
첫 런 내부 진행 = 프리셋 티어의 적 조합·수·웨이브·기믹
이어하기        = 루프 단계의 체력·공격력 강화
실제 성장 결과  = 적 스탯 및 프리셋 선정에 사용하지 않음
```

플레이테스트에서 Tier 2·3의 적이 패턴을 수행하기 전에 반복적으로 정리되거나 티어 체감이 사라질 때는 조합과 배치, 웨이브 구성, 티어 고정 스탯 보정 순서로 강화한다. 이 보정은 프리셋 데이터에 고정하며 실제 플레이어 성장에는 반응하지 않는다.

## 4. 공통 프리셋 규모

초기 구현은 티어당 3개, 총 9개 기본 프리셋으로 제한한다.

- 모든 프리셋은 2~3웨이브다.
- 1웨이브 일반 전투는 초기 범위에서 제외한다.
- 프리셋별 A/B variant는 밸런스 비용 때문에 보류한다.
- 반복감이 실제로 확인된 프리셋에만 후속 variant를 추가한다.

PR #240 설계 기준 플레이어가 한 경로에서 방문하는 방은 보스 포함 9~11개다. 보스방 2개와 보물·제단방을 제외하면 일반 전투 프리셋을 소비하는 방은 대체로 6~8개이므로, 9개 프리셋으로 한 런의 경로 내 비중복을 지원할 수 있다.

표에서 사용하는 기호는 다음과 같다.

| 기호 | 적 |
|---|---|
| `C` | 추격자(chaser) |
| `S` | 사수(shooter) |
| `P` | 분열체(splitter) |
| `H` | 실드 센티널(shield-sentinel) |

아래 수치는 47초 일반방 목표에 맞춰 기존 60초 후보의 전투량을 약 15~25% 줄인 1차 플레이테스트 후보다. 기존 60초 기준도 실측되지 않았으므로 목표시간 비율을 기계적으로 적용하지 않았으며, 47초를 충족하는 최종값으로 간주하지 않는다.

## 5. Tier 1 프리셋

### T1-A 추격 입문

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×3` |
| 2 | `C×3 + S×1` |

- 현재 `room-a`와 같은 기준점이다.
- 근접 대응 뒤 사수를 소개한다.
- 명목상 총 7마리다.

### T1-B 기본 포위

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×2 + S×1` |
| 2 | `C×3 + S×1` |

- 소수 사수를 추격자가 보호한다.
- 두 번째 웨이브에서 근접 밀도를 높인다.
- 명목상 총 7마리다.

### T1-C 단계적 입문

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×2` |
| 2 | `C×2 + S×1` |
| 3 | `C×1 + S×1` |

- Tier 1의 3웨이브 프리셋이다.
- 명목상 총 7마리이며 웨이브 대기는 총 4초 게임 시간이다.

## 6. Tier 2 프리셋

### T2-A 사격진

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×2 + S×1` |
| 2 | `C×2 + S×2` |

- 추격자가 사수 접근과 회피 경로를 방해한다.
- 명목상 총 7마리다.

### T2-B 분열 연쇄

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×2 + S×1 + P×1` |
| 2 | `C×1 + S×1 + P×1` |

- 명목상 총 7마리지만 작은 분열체 때문에 실제 처치 대상은 더 많다.
- 초기 후보 중 장기전 위험이 가장 크므로 우선 측정 대상이다.

### T2-C 강화 포위

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×2 + S×2` |
| 2 | `C×4 + S×1` |

- 첫 웨이브는 다방향 공격, 두 번째 웨이브는 근접 밀도를 강조한다.
- 명목상 총 9마리다.
- 광역과 단일 공격 전략 사이의 시간 편차를 우선 확인한다.

## 7. Tier 3 프리셋

### T3-A 실드 호위

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×2 + S×1` |
| 2 | `C×2 + S×2 + H×1` |

- 1웨이브에서 호위 구성을 보여주고 2웨이브에서 실드 대응과 사격 압박을 결합한다.
- 명목상 총 8마리다.

### T3-B 단계적 혼합

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×2 + S×1` |
| 2 | `C×1 + P×1` |
| 3 | `C×1 + S×1 + H×1` |

- 추격·사격, 분열, 실드 순서로 대응 기믹을 바꾼다.
- 명목상 총 8마리이며 웨이브 대기는 총 4초 게임 시간이다.

### T3-C 복합 사격진

| 웨이브 | 구성 |
|---:|---|
| 1 | `C×1 + S×2` |
| 2 | `C×2 + S×2 + P×1` |

- 원거리 공격과 분열체를 함께 관리한다.
- 명목상 총 8마리다.
- 실드 없이 조합 복잡도와 투사체 압박으로 Tier 3 난도를 만든다.

## 8. 함정방 적용

함정방은 일반방의 9개 프리셋을 그대로 공유하고 `trapProfile`만 합성한다.

- 위험지대
- 침묵
- 암전
- 금언
- 폭염

초기에는 프리셋과 함정의 조합을 임의로 금지하지 않는다. 플레이테스트에서 불공정하거나 목표시간을 반복적으로 초과한 조합만 호환성 제한을 추가한다.

우선 확인할 위험 조합은 다음과 같다.

- 암전 + 사격진: 보이지 않는 원거리 투사체 문제
- 폭염 + 실드 호위: 시간 누적 피해와 처치 지연의 중첩
- 침묵 + 강화 포위: 영창 안전영역의 과밀 문제
- 위험지대 + 단계적 혼합: 3웨이브 장기 체류 문제

함정방과 엘리트 승격은 초기 구현에서 중첩하지 않는다.

## 9. 엘리트방 적용

엘리트방도 일반 프리셋을 공유하되, 모든 적을 무작위 엘리트화하지 않는다. 각 프리셋은 하나의 손 설계 `elitePlan`을 가지며 지정된 적만 승격한다.

공통 제한은 다음과 같다.

- Tier 1·2는 방 전체 엘리트 2마리, Tier 3은 2~3마리를 기본으로 한다.
- 웨이브당 엘리트 1마리를 기본으로 하고 T3-C의 마지막 웨이브만 2마리를 허용한다.
- `guard`와 `unstable`은 각각 웨이브당 최대 1마리다.
- 실드 센티널과 분열체·작은 분열체는 초기안에서 엘리트화하지 않는다.
- 분열체의 자식은 modifier를 상속하지 않는다.
- 엘리트 속성은 런타임 무작위가 아니라 프리셋에 고정한다.

초기 elitePlan 방향은 다음과 같다. 정확한 개체 지정은 데이터 구현 전에 회귀 가능한 슬롯 표현과 함께 확정한다.

| 프리셋 | elitePlan 방향 |
|---|---|
| T1-A 추격 입문 | 1·2웨이브 추격자 1마리씩 `swift`로 승격 |
| T1-B 기본 포위 | 1웨이브 추격자 `swift`, 2웨이브 사수 `guard` |
| T1-C 단계적 입문 | 1웨이브 없음, 2웨이브 추격자 `swift`, 3웨이브 추격자 `unstable` |
| T2-A 사격진 | 1웨이브 추격자 `swift`, 2웨이브 사수 `guard` |
| T2-B 분열 연쇄 | 1웨이브 추격자 `swift`, 2웨이브 추격자 `unstable` |
| T2-C 강화 포위 | 1웨이브 사수 `guard`, 2웨이브 추격자 `unstable` |
| T3-A 실드 호위 | 1웨이브 추격자 `swift`, 2웨이브 사수 `guard` |
| T3-B 단계적 혼합 | 1웨이브 추격자 `swift`, 2웨이브 추격자 `unstable`, 3웨이브 사수 `guard` |
| T3-C 복합 사격진 | 1웨이브 사수 `swift`, 2웨이브 추격자 `guard`와 사수 `unstable` |

이 구조는 기본 프리셋 9개와 고정 엘리트 버전 9개를 관리하며, 프리셋과 독립된 엘리트 오버레이를 곱해 조합 수가 폭증하는 것을 막는다.

Tier 1은 `swift` 반복 학습에서 `guard`, `unstable` 순으로 속성을 소개한다. Tier 3에서만 한 웨이브 2엘리트를 허용해 속성 조합 자체가 후반 난이도를 담당하도록 한다.

## 10. 프리셋 선정

production 선정은 MapGraph 방 진행 통합 뒤 연결한다. 프리셋 데이터와 선택기는 Phaser 비의존 순수 모듈로 선행 구현할 수 있다.

```ts
interface CombatPresetSelectionContext {
  progress: number;
  routeRisk: 'low' | 'balanced' | 'high';
  usedPresetIds: readonly string[];
  runSeed: number;
  nodeId: string;
}
```

루프 단계는 프리셋 선정 입력에 포함하지 않는다. 이어하기 난이도는 별도의 체력·공격력 배율이 담당하며, 루프에 따라 더 높은 티어까지 선택하면 두 축이 중복된다.

선정 순서는 다음과 같다.

1. 전체 런 진행도로 기본 티어를 계산한다.
2. 경로 위험도로 기본 티어와 인접 티어 후보를 만든다.
3. 현재 방문 경로에서 이미 사용한 기본 프리셋을 제외한다.
4. 시드 기반 결정적 난수로 후보 하나를 선택한다.
5. 방 종류가 `trap`이면 `trapProfile`, `elite`면 해당 프리셋의 `elitePlan`을 적용한다.
6. 처음 결정된 결과를 런 상태에 저장해 재진입·저장 재개에서 바뀌지 않게 한다.

일반·함정·엘리트방은 하나의 `usedPresetIds`를 공유한다. 같은 런에서는 오버레이가 달라도 같은 기본 프리셋을 다시 쓰지 않는다.

후보가 부족할 때의 우선순위는 다음과 같다.

1. 현재 티어의 미사용 프리셋
2. 인접 티어의 미사용 프리셋
3. 모든 9개를 소진한 경우 가장 오래전에 사용한 프리셋
4. 직전 방 프리셋은 연속 재사용 금지

중복은 그래프 전체가 아니라 플레이어가 실제로 방문하는 경로를 기준으로 본다. 서로 배타적인 분기 노드는 같은 프리셋을 가질 수 있다.

## 11. DEV 플레이테스트 지원

프리셋과 MapGraph 런타임이 실제로 연결되어 플레이테스트 환경을 구성할 때 다음 DEV 도구를 함께 구현한다.

### 강제 선택

- 프리셋 ID 강제 지정
- 일반·함정·엘리트 모드 지정
- 함정 프로필 지정
- Tier 1 기본 상태 또는 Tier 2·3 대표 성장 로드아웃으로 즉시 시작

### 룸 타이머

- 첫 웨이브 생성 시 시작
- 마지막 적 사망 시 종료
- 룸 활성 실제 시간과 누적 게임 시간을 함께 기록
- 웨이브 사이 2초 게임 시간 대기 포함
- 입장·보상·포탈 시간 제외
- 새 방 진입 시 자동 초기화
- 배포 빌드에서는 표시하지 않음
- 입력창 열림·제출·판정 완료·시퀀스 시작·종료·다음 입력창 열림 시각 기록
- 웨이브별 스폰·전멸의 실제 시간과 게임 시간 기록
- 영창 횟수와 측정용 `playerPowerIndex` 기록

표시 예시는 다음과 같다.

```text
DEV · 일반방 테스트
프리셋: T2-A 사격진
실제 시간: 00:47.3
게임 시간: 00:29.8
웨이브: 2/2
영창: 3회
W1: 실제 21.4s · 게임 13.7s · 대기 2.0 game-s
목표: 47s
```

클리어 후 프리셋 ID, 티어·경로 위험도, 방 종류, 실제/게임 시간, 웨이브별 시간, 영창 횟수와 성장 보조값을 화면에 잠시 유지하고 콘솔에도 출력한다.

## 12. 구현 및 검증 순서

1. 이 문서의 9개 프리셋과 elitePlan을 데이터로 옮긴다.
2. 티어·경로·사용 이력·시드를 입력받는 순수 선택기를 구현한다.
3. 티어 범위, 결정성, 중복 방지, 후보 소진 fallback을 회귀 검증한다.
4. MapGraph 런타임 통합 뒤 실제 일반·함정·엘리트 노드와 DEV 타이머에 배선한다.
5. Tier 1은 기본 상태, Tier 2·3은 해당 구간의 대표 성장 상태로 일반방 9개를 1차 측정한다.
6. Tier 2·3을 성장치 0으로 별도 실행해 프리셋 자체 난이도 기울기를 확인한다.
7. 명백히 짧거나 긴 프리셋을 조정하고 필요한 후보만 반복 측정한다.
8. 함정·엘리트는 대표 조합과 위험 조합을 우선 플레이테스트한다.
9. 후반 적이 패턴을 수행하기 전에 반복적으로 정리되는지 전체 런에서 확인한다.
10. 티어 체감이 부족하면 조합·배치, 웨이브 구성, 티어 고정 스탯 순서로 강화한다.
11. 이어하기 체력·공격력 계수와 기대 성장 기회 보정 필요성은 별도 통합 플레이테스트로 확정한다.

## 13. 보류 사항

- Tier 2·3 대표 성장 로드아웃의 정확한 구성
- 프리셋별 최종 적 수와 목표시간 통과 여부
- 개별 프리셋의 정상 시간 관찰 범위
- Tier 경계의 정확한 가중치
- 프리셋·함정 호환성 제한
- 반복감이 확인된 프리셋의 후속 variant
- 티어 고정 체력·공격력 보정의 필요성과 계수
- 이어하기 기대 성장 기회 보정의 필요성과 계수

이 항목들은 구현 전에 임의로 확정하지 않고 DEV 타이머와 사용자 플레이테스트 결과로 결정한다.
