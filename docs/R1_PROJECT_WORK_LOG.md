## [R1] ESC 일시정지 메뉴 맵 시드 표시

- 실제 게임의 생성 맵을 재현·제보할 수 있도록 생성 직전에 확정한 unsigned seed를 `ProtoScene` 런 상태에 보관하고 ESC에서 나타나는 우측 미니맵 바로 아래에 `맵 시드`로 표시한다. 상단 상태 패널이 늘어나 미니맵 위치가 바뀌면 시드도 함께 이동한다.
- 개발 모드 전용 로그가 아니라 모든 빌드에서 보이는 정식 UI 정보다.
- 시연 로드아웃과 생성 실패 폴백은 생성 시드로 재현되는 맵이 아니므로 임의 숫자를 표시하지 않고 `고정 프리셋`으로 구분한다.
- `test:pausekey`에 실제 생성 결과의 `generated.seed` 저장, ESC 메뉴 표시, 프리셋 구분 계약을 추가했다. `test:pausekey` 7군, `test:mapwiring`, 전체 회귀 92종, production build, `git diff --check`를 통과했다.

- 후속 UI 제안에서는 현재 스테이지만 표시하거나 stage 1·2를 명시적으로 전환·분리하는 방식을 검토한다.

## [R1] 일반방 위험지대 출현 시드 재현

- 플레이테스트 시드 `3934948004`에서 stage 2의 진행상 세 번째 방이 UI상 일반방인데 위험지대 전투가 나온 현상을 재현했다.
- 해당 노드는 `s2n4`, `kind=combat`, `waveSetId=room-c-hazard`다. 생성기가 trap을 combat으로 오분류한 것이 아니라 `mapGenerator.ts`가 stage 2 combat 노드에 `room-c-shield` 또는 `room-c-hazard`를 배정하고, 후자의 wave `hazard=true`가 전투 위험지대를 생성한다.
- 이 변형은 별도 함정방 계약 도입 전 고정 Phase 4 런에서 일반 전투 변주로 쓰던 레거시였다. 생성 맵 combat 풀과 기본 `RUN_ENCOUNTERS`에서 `room-c-hazard` 연결을 제거해 붉은 원형 위험지대는 `kind=trap` + `trapProfile=hazard`에서만 나오도록 확정했다.
- 제보 시드와 500시드의 모든 생성 노드에서 `room-c-hazard`가 나오지 않는 회귀를 추가했다. `test:mapgen`, `test:run`, `test:mapgraph`, `test:mapwiring`, `test:floorhazardwiring`, 전체 회귀 92종, production build, `git diff --check`를 통과했다. 일반·엘리트방의 소규모 독·용암 바닥지형은 별도 정화 가능 지형 체계이므로 유지한다.

- #240 최종 커밋 `9d7e311`의 실행 알고리즘을 `partitionMapGeneratorCore.ts`에 직접 이식했다. 파티션 구성, 갈래 길이·초기 profile, 방 조합, 보상 최소, 파티션/전체 경로 재조정, 합류 보상 보정, 경로 다양화, 지배 경로 수선, 전체 슬롯 특수방 탐색 순서를 보존했다.

- #240은 위험·보상 지배 관계를 스테이지 내부 선택지끼리 비교한다. 두 스테이지의 선택지를 곱한 전체 런 조합에 별도 지배 금지를 적용하던 #312 회귀는 원안 밖의 제약이므로 스테이지별 검사로 복구했다.

## [R1] 과대해석형 필살영창 v1

- 필살영창 v1은 일반 Judge 1~7번을 그대로 두고 요청 `castMode=ultimate`일 때만 별도 계약을 추가하는 방식으로 분리했다. 핵심 의도와 effect 경계를 보존하면서 power 100 고정, 4~8 sequence, form 총 6~12, 최소 한 병렬 form 단계, 마지막 결말 form, duration 4000~6000ms, 맥락상 가능한 원소 1~8개를 요구한다.
- 출력에는 과대해석된 제목 `name`과 전체 해석 `interpretation`만 추가한다. 단계별 `caption`은 전투 중 읽기 어렵고 behavior와 중복되며 출력량을 늘려 제거했고, sequence 객체의 허용 키를 `durationWeight|behaviors`로 제한했다. validator가 일반/필살 계약을 분리하고 resolver는 필살영창에만 최대 6000ms와 마나 비용 0을 허용한다.
- 기존 융합 게이지를 Shift+Enter 필살영창 자원으로 연결했다. 게이지 부족은 요청 전에 거부하고 원격 실패·fizzle·invalid plan에서는 보존하며, 유효한 필살 plan 실행 직전에만 전량 소비한다. DEV에서는 `VITE_FORCE_ULTIMATE=1` 또는 URL `#ult`로 강제할 수 있다.
- caption 제거 후 캐시 버전을 `meaning-v2.22-ultimate-no-caption`으로 올리고 `wrangler.local.toml`로 실험 Worker `948a2021-500a-4860-bf94-0953ce0ee34f`을 배포했다. 원격 `파이어볼`과 `달을 삼킨 파도` 모두 caption 없이 4 sequence·6~7 form·power 100을 생성했다. 두 측정은 계약 교정 1회 때문에 wall 4.65~4.87초였으므로 caption 제거만으로 지연 개선이 보장되지는 않으며 재판정 빈도가 더 큰 변수로 남았다.
- 재요청 제거를 위해 별도 근거가 없는 필살영창의 기본 골격을 4 sequence, form 분포 `1-2-2-1`로 명시했다. 이 골격은 도입·병렬 증폭·병렬 수렴·결말과 form 하한 6개를 동시에 충족하며 입력이 더 많은 사건을 명확히 요구할 때만 확장한다.
- 1차 최초 응답 10종은 구조 골격 10/10을 충족했으나 `배고프다`에서 비지원 `nature` 원소가 나와 실제 클라이언트 계약은 9/10이었다. 원소 enum과 순수 공격 damage-only·순수 지원 목적 보존을 다시 명시한 2차 20종은 원본 19/20이었고, 같은 `nature` 별칭 문제만 반복됐다.
- 임의의 미지원 원소를 보정하지 않고 모델이 반복 생성한 자연 별칭 `nature|plant|flower`만 `earth`로 접는 결정적 정규화를 추가했다. 이를 포함하면 20/20이 4 sequence·6 valid form·병렬·피날레·interpretation 계약을 충족했다.
- JSON 문법 교정과 의미 계약 교정에 쓰던 두 번째 `requestGemini` 경로를 모두 삭제했다. 현재 주문 판정 경로의 `requestGemini` 호출 지점은 하나뿐이며 일반·필살영창 모두 최대 1회다. 복구 불가능한 JSON은 즉시 502/fallback, 구조 위반은 `suppressed-*` 진단과 클라이언트 거부·게이지 보존으로 처리한다.
- 캐시 버전은 `meaning-v2.24-all-single-attempt`, 최종 `wrangler.local.toml` Worker는 `9533bc1e-588c-474c-be74-1751a01f0a88`이다. 최종 원격 `파이어볼`, `배고프다`, `모두를 지켜라`는 모두 attempts 1·4 sequence·6 form·power 100·2.64~2.70초였고 각각 damage-only, heal+buff, shield-only를 유지했다. 일반 `겨울 정원의 폐막`도 attempts 1과 로컬 원소 제한을 확인했다.
- 보호형 필살영창의 허전함은 damage를 강제하지 않고 전장 구조를 남기는 방식으로 보완했다. 순수 보호 입력은 최소 하나의 shield wall을 포함하고, 병렬 단계에서 복수 wall 또는 wall+shield zone을 우선하며 arc|line|ring|polygon shape를 활용하도록 했다.
- 캐시 `meaning-v2.25-ultimate-shield-wall`, `wrangler.local.toml` Worker `eb60da38-0f47-40c2-a2c4-bc5b6c2be804`에서 보호형 8종을 측정했다. 8/8이 wall을 포함하고 6/8이 복수 wall을 사용했으며 ring·polygon shape와 wall+zone 병렬 구조가 확인됐다. 모든 응답은 attempts 1이었다. `어둠이 닿지 못하는 성역` 한 건은 보호·배제 이미지를 복합 의도로 읽어 damage가 섞였으므로 실제 플레이에서 effect 경계 확인이 필요하다.

- 공명은 필살영창 요청에만 압축 전달하고 같은 입력이라도 공명별로 클라이언트 캐시를 분리한다. Worker는 enum과 길이를 다시 제한하며 현재 입력의 명시적 effect 경계를 최우선으로 둔다. 현재 입력과 충돌하지 않으면 선두 공명 원소를 실제 plan의 주 시각 원소로, 선두 form을 도입부·중간부에 사용하고, 최신 영창은 마지막 sequence의 확대·변형된 피날레로 고정한다. interpretation에도 계승 관계를 자연어로 드러내되 과거 effect는 현재 plan effect 결정에 사용하지 않는다.
- 판정 실패·fizzle·invalid plan은 게이지와 공명을 함께 보존하고 유효 필살 plan 소비 또는 명시적 reset에서만 둘을 초기화한다. 중간안 `meaning-v2.30-ultimate-resonance-climax`, `wrangler.local.toml` Worker `5bfb23b1-600b-44a9-b289-7a04690e17d5`에서는 fire·wall 1위와 최신 `번개 사슬` 이력을 명시 공격·보호 양쪽 피날레에 강제하는 방식을 검증했다.
- 후속 검토에서 v2.30의 선두 원소·form 및 최신 주문 피날레 강제가 현재 필살 입력의 과대해석을 약화할 위험을 확인했다. 최종 v2.31에서는 현재 입력만 제목·주원소·전체 sequence·핵심 목적·결말을 결정하고, 공명은 호환될 때 전체 6~12 form 중 1~2개 장면이나 피날레의 보조 form에만 흔적을 남기는 재료로 완화했다.
- 필살영창 effect는 순수 공격 damage-only·순수 보호 support-only의 배타 규칙 대신 핵심 목적과 장면 인과를 사용한다. 공격에서 knockback·slow·weaken, 구속에서 damage, 보호벽에서 접촉 damage·buff, 치유 영역에서 buff·적 slow처럼 직접 파생되는 인접 effect를 허용하되, 별개 볼거리를 위한 무관한 effect는 금지한다.
- 전투 중 긴 설명과 출력 비용을 줄이기 위해 `interpretation`을 Worker 필수 계약·클라이언트 plan 타입·validator·화면 표시에서 제거했다. 제목은 현재 입력을 과대해석하고, 공명은 실제 form 이름과 짧은 로컬 공명 표시에 맡긴다.
- 최종 캐시는 `meaning-v2.31-ultimate-resonance-echo`, `wrangler.local.toml` Worker는 `c2035fc1-4251-4fb1-ae68-095657c3d07e`이다. 화염·번개 이력에서 `달이 바다에 추락한다`는 dark/ice/light/water 중심을 유지해 공명이 전체 설계를 지배하지 않았고, `거대한 해일이 적을 삼킨다`는 `번개 사슬의 격류` 한 장면과 damage+control, `모두를 지켜라`는 shield+buff+control로 생성됐다. 세 결과 모두 interpretation을 출력하지 않았다.
- `test:fusion` 9개 그룹, `test:judge-fallback` 7개 그룹, `test:spell`, production build, `node --check proxy/worker.js`, `git diff --check`를 통과했다. 실제 한 런에서 여러 일반 영창을 누적한 뒤 필살영창의 체감 연결성은 플레이어 테스트가 남았다.

### 주요 구현 결과

#### 소스 구조와 역할 경계

- R1 전용 전투 로직은 `src/combat-core/` 아래의 `combat`, `enemies`, `player`, `waves`로 구성한다.
- 여러 역할이 함께 사용하는 `src/render/`, `src/scenes/`와 공용 진입점 `src/main.ts`는 최상위 위치를 유지한다.
- R2 계약 영역인 `src/spell/`도 최상위 위치를 유지한다.
- `ProtoScene`과 주문 렌더러는 `SpellSpec`을 참조하되 R2 스키마 구조를 변경하지 않는다.

#### 플레이어와 카메라

- WASD로 이동하며 대각선 입력 시 속도를 정규화한다.
- 카메라는 플레이어를 부드럽게 추적하고 HUD는 화면에 고정된다.
- 영창 입력 중에는 플레이어 이동을 차단하고 게임 진행 시간을 10%로 낮춘다.
- 플레이어 상태는 HP 100, 마나 100을 기준으로 관리하며 마나 비용과 글로벌 쿨다운을 검사한다.

#### 적과 피해 처리

- 추격자는 플레이어를 직선으로 추적하고 개체별 쿨다운으로 접촉 피해를 준다.
- 사수는 선호 거리를 유지하면서 3발 확산 탄막을 발사하고 접촉 피해도 준다.
- 대형 분열체는 처치 시 소형 분열체 2기로 나뉘며, 소형까지 모두 처치해야 웨이브가 끝난다.
- 기본 공격은 가장 가까운 적을 추적하고 적중 즉시 사라지며 관통하지 않는다.
- 주문 피해의 1차 공식은 `round(power)`이며, 폼별 최종 밸런스는 후속 작업으로 남겼다.

#### 웨이브와 주문 폼

- 웨이브 1: 추격자 3기
- 웨이브 2: 추격자 2기 + 사수 2기
- 웨이브 3: 추격자 2기 + 사수 2기 + 대형 분열체 1기
- 마지막 활성 적을 처치하면 웨이브 완료 또는 `ROOM CLEAR` 상태로 전환한다.
- `beam`은 목표 방향의 직선 범위를 관통하며 범위 안의 적을 각각 한 번 타격한다.
- `wave`는 넓은 파면이 전진하며 닿은 적을 각각 한 번 타격한다.
- `size`, `speed`, 주·보조 원소 팔레트를 두 폼의 크기·속도·색상에 반영한다.

### 구현 내용과 임시 결정

- `zone`은 최대 320px 안의 밀집 위치에 기본 반경 130px로 고정 설치되며, 넓어진 범위 대신 총 `power × 0.8`의 피해를 10회로 나눠 준다.
- `rain`은 최대 520px 안의 밀집 목표 영역에 6개의 원소 낙하물을 분산시켜 각 착탄마다 범위 피해를 준다.
- 두 광역 폼은 가장 가까운 적을 고정 조준하지 않고, 사거리 안에서 현재 가장 많은 적을 포함하는 적 위치·중간점을 자동 선택한다.
- `beam`과 `wave`도 각 적 방향과 적 사이의 중간 각도를 비교해 실제 직선·파면 폭으로 가장 많은 적을 맞히는 방향을 선택한다.
- `size`는 범위를, `speed`는 지속·전개 시간을 변경한다.
- 각 회차에 `damageMultiplier`와 `hitGroup`을 전달해 프레임 중복 피해는 막고 의도된 반복 타격은 허용한다.
- damage 주문은 분할된 power 피해를, control 주문은 같은 적중 영역에서 직접 피해 없이 둔화를 적용한다.
- control 장판은 일반 control의 2~6초 지속시간 대신 틱마다 0.5초만 갱신해 장판 종료 뒤 빠르게 해제한다.
- 폼별 범위·지속시간·타격 수·피해 배율은 기획 미정 임시값으로 로컬 가정 문서에 기록했다.

- 보스 대시 경고는 기존 채움 삼각형을 유지하면서 통로 테두리 안쪽으로 옮기고 도착 원은 제거했다. 경고 레이어는 보스 아래에 유지한다.
- 자동 각인·정령 공격에도 내성 피해 배수는 적용하되 경고 문구는 직접 영창에만 표시한다. zone 등 지속 영창은 한 영창당 경고를 최대 한 번만 표시한다.
- 최종 기억 보스는 페이즈 1의 이전 런 부분 내성(×0.6)을 유지한 채 페이즈 2에서 현재 런 강한 내성(×0.3)을 추가한다. 같은 원소면 ×0.3 하나로 강화하고, 서로 다르면 피해 계산·HUD·이중 링에 두 내성을 함께 표시한다.

- 주문서 역직렬화 시 원소·폼 enum, power 범위와 문자열 길이를 검증하고 비정상 저장 데이터 회귀를 추가했다.

### 구현 내용과 결정

- 초기에는 Issue #77의 `시야 축소 → 광역·설치형 주문의 가치 상승`을 주문별 국소 광원으로 구현했다. 플레이테스트 결과 광역기 자체로 적이 정리되거나 마나가 소진돼 밝혀진 시야의 후속 활용이 어려웠고, 폼별 광원 추적은 규칙 전달도 불명확해 폐기했다.
- 최종 프로토타입은 빛·불꽃 속성의 **직접 영창**이 시야 반경을 2배로 넓힌다. 정령·각인·주문서 자동 발동은 제외해 플레이어가 의식적으로 원소를 섞어야 한다.
- 기본 시야 반경은 95px이며 최외곽은 약 96% 암도로 실루엣만 희미하게 남긴다. 기본 상태에는 18% 전역 음영을 추가해 중앙 시야도 평소보다 살짝 어둡다. 빛·불꽃 영창 후 이 음영이 사라지면서 시야 반경이 전투 시간 4초 동안 2배로 확장된다. 종료 시 원 경계를 안쪽으로 움직이지 않고, 기본 반경/2배 반경의 고정 마스크와 전역 음영을 0.8초간 교차 페이드해 자연스럽게 어두워진다.
- 조명 시간은 현실 시간이 아니라 전투 시간으로 감소한다. 영창 입력 슬로모션 중 시간이 거의 소진되지 않아 밝혀진 시야를 다음 주문에 활용할 수 있다. 연속 발동은 남은 시간을 초기화한다.
- 암전 렌더러는 플레이어 주변 기본/2배 반경의 5겹 그라데이션 역마스크 두 세트와 교차 페이드 값만 소유한다. 폐기한 임시 광원 배열·폼별 이동 콜백·광륜 렌더링은 모두 제거했으며 별도 암전 해제 텍스트도 띄우지 않는다. 방 진입 안내도 `빛/불꽃 기술을 쓰면 밝아집니다`로 단순화했다.
- 보스 탄막·돌진·장판 예고처럼 회피에 필수인 정보는 암전 위에 남긴다. HUD·영창 UI도 월드 암전의 영향을 받지 않는다.
- 저주를 의도에 따라 `movement`·`element`·`casting` 카테고리로 먼저 나눈다. 후보가 있는 카테고리 중 최대 2개를 결정적 랜덤으로 고른 뒤, 각 카테고리 내부에서는 직전 런 행동 가중치가 가장 높은 저주 1종을 선택해 저주방에 교대로 배분한다. 현재는 이동 카테고리의 침묵과 원소 카테고리의 암전만 있어 둘 다 자동으로 선택된다. `casting`은 주문 반사 같은 후속 저주를 위한 빈 카테고리다.
- 스테이지마다 교대 인덱스를 초기화하면 짧은 스테이지에서 침묵만 나오는 문제를 수정해, 선택된 카테고리별 저주를 런 전체 순서로 교대한다.
- 기존 `RunMemory`에 하위 호환 선택 필드 `lastCurseBehavior`를 추가했다. 런 중 실제 이동 거리와 성공 직접 영창 수·빛/불꽃 직접 영창 수를 저장하며, 필드가 없는 기존 저장 데이터는 모두 0인 기본값으로 정규화한다.

### R1 수행 작업과 협업 경계

- **R1 수행 작업**: `a>b(n)` 파티션 문법, 스테이지 방 예산·루트 위험/보상·방 종류 우선순위, 시드 기반 HTML 시뮬레이터, `MapGraph` 계약/프리셋/검증을 구현했다.
- **R2/R3 작업 경계**: 실제 방 전환·포탈·미니맵 소비, 보상/제단의 최종 위험도·보상 기대치 튜닝, 생성된 그래프의 런타임 선택과 저장은 후속 통합 범위다.

### 주요 결정

- 파티션은 시작 분기 수 `a`, 종료 분기 수 `b`, 평균 경로 길이 `n`을 갖는 `a>b(n)`으로 표현한다. 분기는 최대 3개로 제한하고, 선형·분기·합류를 조합해 DAG를 구성한다.
- 루트 선택의 의미를 유지하기 위해 위험도가 높은 경로에는 상대적으로 높은 보상을 배치하되, 전체 노드 기준 전투/비전투 비율과 방 종류 다양성을 함께 고려한다.
- 생성 제약은 안전성/도달성, 스테이지당 보상방 최소 1개, 루트 위험·보상 정합성, 방 종류 다양성, 전투·비전투 및 전투방 유형 비율 순서로 검증한다.
- HTML 시뮬레이터로 시드별 구조·방 구성·예상 런타임을 확인하고, 코드 감사기로 다수 시드의 제약 위반 여부를 점검했다.
- Phaser 의존성이 없는 `MapGraph` 모듈과 계약·프리셋·회귀 스크립트를 먼저 구현해, 후속 런타임 통합에서 그래프 생성 규칙을 재작성하지 않도록 했다.

### 후속 사운드 패스 사전 승인 범위

- 타이틀 배경음악, 보상·제단방 배경음악, 런 완료 효과음은 이후 별도 합의 없이 후보 제작·선정·구현까지 진행할 수 있다.

- 보상방과 제단방은 감정적 기능이 달라 같은 곡을 공유하지 않고 별도 BGM으로 제작한다. 타이틀·보상방·제단방 세 곡은 기존 전투 BGM과 같은 `dark arcane electronic` 계열의 음색으로 통일하되 에너지·화성·긴장도를 분리한다.
- Adobe Firefly Generate Soundtrack용 90초 프롬프트는 공통으로 instrumental, controlled low end, clear midrange, stable middle section, no abrupt ending을 요구해 SFX 가독성과 후속 루프 편집 여지를 확보한다. 아직 후보 생성·청취·채택은 수행하지 않았다.
- 생성된 90초 WAV 3종으로 루프를 만들었다. 타이틀 1차안은 경계가 부자연스러워 폐기했고 V2A/V2B 승인안 중 더 긴 V2B를 채택했다. 최종 구간은 타이틀 9.0~72.5초(61.0초), 보물방 12.0~72.0초(57.5초), 제단방 11.0~64.0초(50.5초)이며 모두 2.5초 equal-power 크로스페이드와 -6dBFS 피크를 적용했다.
- 런 완료음은 재생성 C/D 중 고역 에너지가 거의 없고 중역 정보가 더 많은 `runcomplete_d.wav`를 채택해 2.000초에서 1.690초로 무음 정리하고 -7dBFS로 정규화했다.
- 최종 OGG 7개를 추가하고 `GameAudio`에 `title|reward|altar` BGM과 `run-complete` SFX를 등록했다. 타이틀 씬은 타이틀 트랙만 별도 preload하며, 무전투 보물방·제단방 진입 시 각 전용곡으로 전환하고 다음 전투방에서 combat BGM으로 복귀한다. 런 완료음은 사망 선점 검사를 통과한 실제 승리에서만 재생한다.
