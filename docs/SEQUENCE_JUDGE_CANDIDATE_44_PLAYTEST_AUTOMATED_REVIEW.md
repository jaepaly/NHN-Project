# 후보 44 추상·시적 30종 — 자동·정적 검토

## 범위와 판정 경계

- 실험 Worker 후보 44에 체크리스트 30종을 각 1회 실제 호출했다.
- 응답의 HTTP 상태, 지연, JSON·스키마 표면 계약, 단일/plan 구조, 원소·effect·form,
  move·wait, 중첩 power/cost를 검사했다.
- 저장된 JSON을 기대 이미지와 대조해 의미·주체·사건 보존을 정적으로 검토했다.
- 실제 화면의 타격감·연출 가독성·재미는 이 검토로 확정하지 않는다.

## 정적 의미 검토

이 평가는 화면을 보지 않은 JSON 기준의 사전 분류다.

| 분류 | 수 | 의미 |
|---|---:|---|
| 통과 후보 | 21 | 핵심 이미지·주체·효과·사건 구조가 대체로 보존됨 |
| 플레이 확인 필요 | 5 | 해석은 가능하지만 과잉 안무·축약·방향 문제가 의심됨 |
| 수정 후보 | 4 | 핵심 이미지 소실 또는 의미 안정성 문제가 구조에서 확인됨 |

### 플레이 확인 필요

1. `적막을 가르는 섬광`
   - light/dark slash는 강렬하지만 입력에 없는 player 돌입 move가 붙었다.
   - 실제 화면에서 장식용 이동이 주문을 더 좋게 만드는지 확인한다.
2. `무지개를 한 자루 창으로`
   - light+water 단일 bolt로 수렴했다.
   - 수렴 이미지는 지켰지만 무지개의 다색성이 화면에서 충분한지 확인한다.
3. `밤의 틈새에 이름을 묻는다`
   - dark+light 자기 buff, “자취를 감춘다”로 해석했다.
   - `이름을 묻는다`의 봉인·호명 이미지가 지나치게 약해졌는지 확인한다.
4. `마지막 종이 울리기 전에`
   - light control wave 하나로 나왔다.
   - 시간 제한과 선제 행동의 긴장감이 화면에서 읽히는지 확인한다.
5. `어둠이 나를 삼켰다가 적 뒤에 뱉는다`
   - dark move+shield 뒤 move+slash의 2단계다.
   - 두 번째 destination이 `away-from-target`이어서 실제로 적 뒤에 나타나는지 확인한다.

### 수정 후보

1. `화산맥의 기상`
   - 최초 출력에 지형의 각성을 player의 `arena-center` 이동으로 오해한 move가 생겼다.
   - 반복 3회도 단일 nova, move+wave→nova, 자기 buff로 갈려 핵심 해석이 불안정했다.
2. `왕좌를 잃은 번개`
   - large lightning bolt 하나로 끝나 “왕좌를 잃은” 난폭함·반역·추적 이미지가
     사실상 flavor에만 남았다.
3. `한겨울이 심장을 두드린다`
   - 단일 slow control wave로 나와 심장 박동의 반복·시간 리듬을 잃었다.
4. `별들이 추락을 거부한다`
   - light 자기 buff 하나로 축약되어 별 형상의 정지·역상승 사건이 화면 behavior에 없다.

## 의미 안정성·지연 반복

최초 호출에서 2.2초 이상이었던 사례 중 단일 2.5초 timeout과 가까운 세 입력을
각 3회 다시 호출했다.

| 입력 | HTTP 200 | 지연 범위 | 구조 안정성 |
|---|---:|---:|---|
| 화산맥의 기상 | 3/3 | 1.470~1.903초 | 낮음 — single/plan/buff로 변동 |
| 베어낸 자리엔 나만 없다 | 3/3 | 1.393~2.169초 | 높음 — 3/3 slash+move |
| 죽은 숲이 발목을 붙든다 | 3/3 | 1.410~1.500초 | 높음 — 3/3 control, cage/wall 변형 |

최초 30회와 반복 9회를 합쳐 39/39가 HTTP 200이며 2.5초를 넘은 호출은 없다.
`죽은 숲이 발목을 붙든다`의 최초 2.422초는 반복 시 재현되지 않아 단일 지연
표본으로 남긴다.

## 로컬 회귀와 빌드

- 첫 `npm test`는 샌드박스가 병렬 esbuild의 상위 경로 열람을 차단해
  69개가 동일한 접근 오류로 중단됐다. 코드 실패로 계산하지 않았다.
- 권한 환경에서 같은 명령을 재실행해 회귀 70/70이 모두 통과했다.
- 최종 `npm run build`도 권한 환경에서 통과했다.
- 기존 chunk 크기 경고만 있으며 새 오류는 없다.

## 결론

후보 44는 스키마·실행 계약과 응답 지연 면에서 종합 플레이테스트가 가능한 상태다.
추상 입력도 effect·form 분포가 단일 공격으로 완전히 평준화되지는 않았다.

다만 실제 플레이에서 우선 확인할 사례는 `적막을 가르는 섬광`,
`무지개를 한 자루 창으로`, `밤의 틈새에 이름을 묻는다`,
`마지막 종이 울리기 전에`, `어둠이 나를 삼켰다가 적 뒤에 뱉는다`다.

정적 수정 후보 4종은 플레이 결과로 문제가 재확인되면 개별 문구 암기보다
`지형 주체`, `상태 변화 수식어`, `함축된 반복`, `형상 반전`의 공통 규칙으로
교정한다.

## 사용자 플레이테스트 1차 피드백

- 추상 영창에서 사용자는 공격 주문을 기대했지만 control·utility가 나온 사례가
  체감상 조금 있었다.
- 같은 30종 원격 표본을 “damage form 포함 여부”로 다시 집계하면
  damage 15종, damage 없는 control 8종, shield·buff·heal 7종이다.
- 입력군 자체에 비공격 기대 사례가 포함되어 있어 이 분포만으로 실패율을 정할 수는
  없지만, 모호한 추상 표현에서 control·buff를 안전한 기본값처럼 선택하는 경향은
  후속 후보에서 확인할 가치가 있다.
- 후속 조정은 모든 추상 영창에 damage를 강제하지 않는다. 적대적 주체·충돌·절단·
  파괴·추락·폭발·사냥처럼 공격성이 강하게 함축될 때 damage에 약한 우선권을 주고,
  보호·회복·속박·정지·성역처럼 비공격 의도가 읽히는 입력은 그대로 보존하는
  방향을 검토한다.
