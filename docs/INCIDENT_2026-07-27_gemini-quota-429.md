# 인시던트 — Gemini 429 / 판정 Mock 폴백 (2026-07-27)

> **요약(TL;DR)**: "모든 판정이 MockJudge로 폴백된다"는 팀원 제보의 원인은 **Gemini 무료 티어 요청 쿼터(프로젝트 단위) 초과**다. 배포 버그도, 토큰 초과도, 워커 코드 루프도 아니다. 라이브 판정 개발이 본격화(7/22~)되며 요청량이 늘었고, **R2의 캐시 시드 생성 스크립트가 429에도 문장당 6회 재시도해 요청을 폭증**시킨 게 결정적 증폭 요인이었다. **간헐적**이며(작성 시점엔 정상 작동) 무료 티어 한계다. **유료 전환은 보류**, 대신 재시도 폭주 제거·캐시 프리워밍으로 요청량을 줄인다.

- **담당**: 임재윤 (R2)
- **상태**: 원인 규명 완료(핵심), quotaId 정밀 확정만 미결(재현 대기)
- **영향**: 무료 쿼터가 순간 초과되는 구간에 친 주문이 실제 Gemini가 아니라 **MockJudge(키워드 폴백)**로 판정됨. 게임은 멈추지 않음(무중단 폴백 설계대로).

## 1. 증상 (팀원 제보, 오늘 오후 1시경)

> 프록시가 502를 내고 있고, upstream 응답은 429 — "You exceeded your current quota". 그래서 모든 판정이 MockJudge로 폴백되고 있습니다. `lastSource`가 전부 `fallback`으로 찍힙니다.

## 3. **확정된 사실** (문서·웹·실측)

### 3.1 429가 두 종류다 (핵심 발견)
- **워커 자체 리미터** — `{"error":"rate limited","limit":15}`. 워커가 **IP당 15/분**으로 스스로 차단(`RATE_LIMIT_PER_MIN`). Gemini에 도달하지 않아 **AI Studio 대시보드에 안 잡힘**. (병렬 연타로 재현 확인.)
- **Gemini upstream 429** — `{"error":"upstream","status":429,"detail":"...generate_content_free_tier_requests, limit: 500, ... Please retry in 13.6s ... RESOURCE_EXHAUSTED"}`. **이게 팀원이 본 것.**

### 3.2 Gemini 쿼터 성격 (공식 문서 + 웹)
- rate limit은 **프로젝트 단위** 집행(키 단위 아님).
- **RPD는 태평양 자정 리셋** ≈ **한국 오후 4~5시**.
- `generate_content_free_tier_requests`는 **quotaId가 2개** — 분당(`...PerMinutePerProjectPerModel-FreeTier`)·일일(`...PerDayPerProjectPerModel-FreeTier`). 같은 metric 이름이라 **quotaId로만 구분**된다.
- 캡처된 에러의 **`limit: 500`은 일일(RPD) 값**(분당은 15) → **일일 쿼터로 강하게 시사**.

### 3.3 간헐적이다
작성 시점(오후) 재측정: **8/8, 5/5 전부 cast 정상**. 지속 장애가 아니라 요청이 몰리는 구간에만 순간 초과 → 그 순간 친 사람만 Mock.

## 4. 미확정 (정직)
- **정확한 quotaId(분당 vs 일일)**: full payload(`detail`)의 `quotaId`를 봐야 확정. 현재 429가 재현 안 돼(쿼터 여유) 못 잡음. `limit 500`은 일일을 가리키나 `retry 13s`는 분당스러워 단정 불가.
- **확정 방법**: 다음에 502가 뜰 때 `detail` 전문의 `quotaId`를 캡처하면 끝. (진단 시 워커 `detail.slice(0, 500)`을 임시로 늘리면 전문이 보인다.)

## 5. 원인 (근거 있는 결론)
1. **7/22~**: 라이브 Gemini 판정 개발 본격화(모델 핀·DSL·시퀀스·프롬프트 튜닝 v2.x). 그 전엔 라이브 사용 ~0이라 429가 날 일이 없었다 → **"갑자기"의 정체는 사용 국면 전환**.
2. **캐시 churn**: 5일간 프롬프트 버전을 **v2.2→…→v2.15로 5~6회** 올림. 버전이 바뀌면 캐시 키가 바뀌어 **기존 캐시 전량 무효** → 같은 문장도 매번 라이브 재호출.
3. **R2 시드 생성 스크립트의 재시도 폭주(결정적 증폭)**: `generate-cache-seed.ts`가 cast 못 받으면 **문장당 최대 6회 재시도**. 429가 뜬 상태에서 6회 더 두들기면 상황을 악화시키며 요청을 폭증 → 오류 차트의 429 스파이크 대부분이 이 스크립트.
4. 결과: 무료 티어 요청 쿼터를 **순간적으로 반복 초과** → 그 구간 판정이 Mock 폴백.

## 6. 결정
- **유료 전환: 보류** (팀 결정). 무료 티어로 데모 감당 가능한지 먼저 본다.
- 대신 **요청량을 줄여** 무료 한도 안에서 버티는 방향.

## 8. 재발 방지 요약
- **원인**: 무료 티어 요청 쿼터(프로젝트 단위)를 개발·테스트 요청량이 순간 초과. 시드 재시도가 증폭.
- **방지**: 재시도 폭주 제거 + 프리워밍 + 버전 안정 + 대량 스크립트 자제.
- **한계**: 데모날 동시 접속이 많으면 무료 티어로는 근본 한계 → 그때 유료 전환 재검토.
