## 3. 영상 스토리보드 (30~60초)

> **갱신 2026-07-23** — L3(#101)가 게이트 통과·확정([GATE_DECISION_0728](GATE_DECISION_0728.md))되어 **몽타주 후보에서 영상의 중심축으로 승격**. 편집 원칙: *오늘 들어온 기능을 다 넣지 않는다.* 60초에 5비트가 이미 꽉 찼고, 기능 나열은 논지를 흐린다. **"AI가 메뉴에서 고르는 게 아니라 행동을 설계한다"** 한 문장만 남기는 게 목표.

## 6. 심사 기간 Gemini 할당량 운영안 (R2 임재윤, 2026-07-24 최신화)

> 최악 케이스: **심사위원이 몰려 Gemini 프로젝트의 활성 요청 한도(RPM/RPD 등)를 소진** → 판정이 429로 실패. 게임은 폴백으로 계속 돌지만 판정 품질이 저하된다.

### 6-1. 현재 사실 (코드·공식 문서 기준)
- 모델: **`gemini-3.5-flash-lite` 안정 버전을 명시 핀**한다. 기존 `-latest` 별칭이 자동 드리프트하며 요청 규격과 판정이 바뀐 전례가 있으므로 **`-latest`는 금지**한다.
- Worker는 `RATE_LIMIT_PER_MIN=15`로 IP·인스턴스별 보호막을 둔다. 이것은 앱 자체 제한이며 Gemini 프로젝트 전체 쿼터를 보장하지 않는다.
- Gemini 한도는 **API 키가 아니라 프로젝트·사용 티어별**로 적용되고 바뀔 수 있다. 고정된 RPM/RPD를 문서에 가정하지 말고 심사 직전 Google AI Studio의 **활성 한도**를 확인한다.
- 2026-07-24 공식 가격표의 Gemini 3.5 Flash-Lite 표준 유료 단가는 입력 **$0.30 / 1M tokens**, 출력(추론 토큰 포함) **$2.50 / 1M tokens**다. 실제 비용은 응답의 `usageMetadata` 입력·출력 토큰을 분리해 다시 계산한다.

### 6-2. 데모 호출 프로필 (캐시 반영)
| 호출 | 빈도 | 캐시 |
|---|---|---|
| 판정 `/` | 신규 문장당 1회 (동일 문장 반복은 0회) | localStorage, `incant:judge:v2:meaning-v2.6-seq:` |
| 보스 대사 `/boss-line` | 보스전당 1회 | 런 요약 키 |
| 진화·융합 `/evolve-name` | 런당 1~2회 | localStorage, `incant:evolvename:name-v1.0:` |

- **빈 캐시 1회 완주 ≈ 18~28 콜** (대부분 판정, 다수는 반복·캐시로 절감).
- 복합 `spell_plan`도 호출 수는 1회지만 단일 주문보다 출력이 길고 지연 tail이 2.5초 폴백 임계에 가깝다. 대표 `spell` 생략 최적화 후 실측 최대 1.99초였으며, few-shot 예시를 늘릴 때는 지연 게이트를 다시 측정한다.
- 완주 가능 횟수는 심사 시점의 활성 프로젝트 한도에서 다시 계산한다. 과거 2.5 모델의 RPD 수치를 3.5 모델에 재사용하지 않는다.
- 비용 추정도 입력·출력 토큰 단가가 다르므로 합산 토큰 하나로 계산하지 않는다. 실제 프록시 응답의 사용량 표본을 기준으로 산출한다.

> **⚠️ C안(능동형 마나) 채택 영향 (#53-5)**: 글로벌 3초 쿨다운이 기본 0.4초 영창 입력락으로 바뀌어 마나가 넉넉하면 한 사용자의 버스트 시전이 Worker의 15 RPM 보호막에 닿아 429→Mock 폴백될 수 있다. 반복 문장은 캐시로 호출 0회지만 변주 입력은 신규 호출이다. 여러 심사위원은 서로 다른 IP일 수 있어 Worker의 IP별 제한만으로 Gemini 프로젝트 전체 쿼터를 보호할 수 없으므로 활성 프로젝트 한도 모니터링이 별도로 필요하다.

> **⚠️ 마나 경제 진화 재점검 (#121·#122)**: 영창 환류(수동 주문 킬 +6)는 지속 시전을 쉽게 해 직접 호출을 늘린다. 감쇠 시전(마나 5 이상)은 비용을 판정한 뒤 적용되므로 네트워크 호출 자체를 새로 만들지는 않지만, 저마나 영창이 결과 있는 행동이 되어 플레이어가 더 자주 시도할 수 있다. 다양성 보너스도 변주 입력(캐시 미스)을 유도한다. **순효과: 이전 경제보다 신규 Gemini 호출 빈도가 높아질 수 있으므로 심사 동시 접속을 실제 활성 한도 기준으로 점검한다.**

### 6-3. 대응 (노력 순 — 위에서부터)
1. **이미 내장 (코드 0 변경)**: localStorage 캐시 + 2.5초 타임아웃 + MockJudge 폴백. **429여도 게임 무중단**(판정 품질만 저하).
2. **동일 브라우저 프리워밍**: localStorage는 브라우저·오리진별이므로 영상·현장 시연에 사용할 바로 그 브라우저에서 대표 문장을 미리 판정한다. Node 스냅샷 실행은 브라우저 캐시를 채우지 않는다.
3. **활성 한도 확인·모니터링**: 심사 직전 Google AI Studio에서 프로젝트의 실제 RPM/RPD를 확인하고, 여러 기기 동시 테스트로 429와 폴백 비율을 기록한다.
4. **유료 티어 검토**: 활성 한도가 예상 동시 접속보다 낮으면 결제·상위 티어를 검토한다. 유료도 무제한은 아니므로 적용 후 표시된 한도를 다시 확인한다.

### 6-4. 권고
- **재현성**: 심사 창 동안 현재 검증된 안정 모델 `gemini-3.5-flash-lite`를 계속 명시 핀한다.
- **용량 결정**: 고정된 옛 RPD 수치나 “유료=무제한” 가정 대신, 심사 직전 AI Studio에 표시되는 활성 한도와 실제 동시 테스트 결과로 무료 유지/유료 전환을 결정한다.
