## R1 — 게임 코어 (Game Core) · 이도원

> 판정 결과를 **실제로 보이고 만져지는 전투**로 만드는 층. 머지 PR 38건.

| 영역 | 실제 산출물 |
|---|---|
| **전투 코어** | Phaser 씬·런 루프, 플레이어 이동·기본공격, 적 6종 행동, 웨이브 스포너, 충돌·피해 판정 |
| **주문 폼 렌더러** | `bolt`·`zone`·`rain`·`chain`·`cage`·`wall`·`orbit`·`nova` — 판정이 내놓는 13종 형태를 실제 전투 판정과 함께 구현 |
| **분기형 맵 그래프** | `RunMapGraph` 순수 모델 + 씬 계약(현재/갈래/진입/스냅샷) 구현, 포탈 배치 계약 — 선형 런을 분기형으로 바꾼 뼈대 |
| **파티션 맵 생성기** | 방 예산 분할 기반 절차 생성 설계 — 고정 프리셋을 실런에서 대체(모든 경로 8방 고정, 폴백률 0%) |
| **런 구조·보스** | 스테이지 보스·기억 보스 패턴, 이중 저항 소비, 저주방(금언·암전) 콘텐츠 |
| **게임필·밸런스** | 히트스톱·카메라 셰이크·넉백, 전투 피드백 폴리싱, 종반 전투 밸런스·방별 런타임 계측 |
| **에셋**(Phase 3~, 본인 희망) | AI 생성 사운드 1~3차 패스(SFX·BGM)·보스전 BGM, 타이틀 화면·내장 웹폰트·파비콘, 방별 배경 색조 |
| **프로토타입** | 능동형 마나 회복 C안(채택되어 시전 경제의 기반이 됨), nova 목표지점 투사체 |

**대표 기여** — *능동형 마나 C안*: 시전 경제 3개 후보 중 이도원이 플레이 가능한 프로토타입으로 만든 안이 팀 채택되어, **"적을 처치해 마나를 얻는다 = 영창하려면 싸워야 한다"**는 현재 코어 루프가 됐다.

## R2 — AI 시스템 (AI Systems) · 임재윤

> 자유 문장을 **구조화된 주문으로 바꾸는 층**과 그 인프라. 머지 PR 62건.

| 영역 | 실제 산출물 |
|---|---|
| **판정 프롬프트** | 의미 우선 판정 규칙 `meaning-v2.4 → v2.31` 진화 — 다국어·비유 해석, 추상 문장→행동 시퀀스 분해, 필살·공명 계약 |
| **LLM 인프라** | Cloudflare Worker 프록시(API 키 은닉·레이트리밋·프롬프트 서버측 고정) → 판정기 교체·지연 계측(Server-Timing)·고정 리전 이전 대응 |
| **폴백 체인** | localStorage 캐시 · 타임아웃 · MockJudge 폴백 — *판정이 실패해도 게임은 멈추지 않는다* |
| **관측성** | 플레이 로그 스키마(세션·런 경계·폴백 원인·upstream 상태 보존) — **완주당 LLM 호출량을 로그로 계량 가능하게** |
| **기억하는 보스** | 주문 히스토리 분석 → 원소 내성·카운터, 런 간 기억, LLM 도발 대사 생성(+쿼터 안전화) |
| **시간축 시퀀스 계약** | 한 문장을 `form`/`wait` 여러 단계로 분해해 **순서와 간격까지** 설계하는 프롬프트. 초기 `move`(움직임 프로그램) 실험을 실측 후 스스로 걷어내고 재구성 |
| **방 콘텐츠** | 보물방·제단방 보상, 바닥형 지형(용암·독지대) — 밟으면 아프고 상성 영창으로 정화되는 환경 |
| **밸런스 리프레임** | 반복 억제를 페널티(채찍)에서 **다양성 보너스(당근)**로 전환 |
| **모델 안정화** | `-latest` 별칭 드리프트 사고 대응 → `gemini-3.5-flash-lite` 명시 핀, 429 인시던트 분석·쿼터 정책 |
| **제출물 오너** | **④ AI 활용 기술 문서** |

**대표 기여** — *판정 계약의 자기 교정*: 프롬프트만으로 LLM이 움직임을 설계하게 만드는 `move` DSL을 먼저 세웠고(신규 묘사 20/20 유효), 이후 **플레이어 조작권과 충돌한다는 판단으로 자기 기능을 걷어내고** `form`/`wait` 시간축 계약으로 재구성했다(#319). 재구성본 실측 30/30 계약 준수·평균 1,443ms. "AI가 메뉴에서 고르는 게 아니라 **설계한다**"는 핵심 주장은 유지하되, 설계 대상을 움직임에서 **시간축**으로 옮긴 판단이다.

| **아트 파이프라인** | AI 생성 스프라이트·배경의 누끼·워터마크 제거, 재질/발광 2층 렌더 분리 |

**대표 기여** — *게이트 결정*: 트랙 B 신규 기능(소환 행동 DSL 등)의 컷/승격을 **감으로 정하지 않고 실측으로 정했다**. 수율 20/20, 판정 폴백 0/10, 오토 화력 비중 실런 2회 측정 — 근거를 문서에 남기고 팀에 전파해 회의 없이 결론을 냈다.

## 협업 방식

- **PR 기반 협업**: 브랜치 작업 → 리뷰 후 머지가 기본 경로 (머지된 PR 279건). 팀원 PR은 총괄이 검증된 리뷰(재현·반박 검증)를 달아 승인·변경요청으로 갈랐다
- **계약 우선(contract-first)**: 역할 경계의 인터페이스(판정 JSON 스키마, 보상 `RewardKind`, 맵 그래프 `MapGraph` 표면, 보스 기억 계약)를 **먼저 커밋해 고정**하고 그 위에서 병렬 작업 — 3인이 서로 다른 에이전트를 동시에 몰 수 있었던 핵심. 실제로 R1 그래프 구현이 계약 6메서드에 정확히 맞춰 도착해 씬 통합이 하루 안에 끝났다
- **회귀로 방어**: 순수 로직 + **씬 배선 검사**를 회귀 스크립트 106종으로 고정. 배선 유실은 화면을 봐야만 아는 종류의 버그라, 코드 문자열 검사로 CI가 잡게 했다. 돌연변이 시험(버그를 심고 회귀가 빨개지는지)으로 회귀 자체의 실효성도 검증
- **AI 사용 즉시 기록**: 작업 직후 [AI_USAGE_LOG.md](AI_USAGE_LOG.md)에 1줄씩 (누적 360건 — 제출물 ④의 원천 데이터)
- **인수인계 문서화**: 기계·AI 세션이 바뀌어도 이어갈 수 있도록 [HANDOFF.md](../HANDOFF.md)에 환경·함정·워크플로 고정

### 역할 간 인터페이스 계약

| 경계 | 계약 |
|---|---|
| R1 ↔ R2 | 판정 JSON 스키마(`SpellSpec`·`SpellJudgement` v2) — 변경 시 양측 합의 |
| R1 ↔ R3 | 보상 계약(`RewardKind`·`RunController` 이벤트), 맵 그래프 표면(`MapGraph` 6메서드 — R1 소유 순수 모델, R3 소비), 씬 전환 |
| R2 ↔ R3 | 영창 UX 타이밍(판정 대기 연출), 보스 대사 포맷, 시퀀스 `form`/`wait` 스키마 |

> 제출물 ①(빌드+소스)은 **전원 공동 책임** — 배포 파이프라인은 R3가 관리.
