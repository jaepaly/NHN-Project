### 대표 기여 ① — 영창 시퀀스 판정을 실측으로 재구성 (#203 → #319)

"한 문장을 시간축 위의 여러 단계로 푼다"는 이 게임의 핵심 계약을 **감이 아니라 계측으로** 세웠다.

먼저 초기 시퀀스 설계 30종과 라이브 판정 사이의 간극을 쟀다 — 단계 수가 일치한 사례 4종, 초기 병렬 18종 중 병렬을 유지한 것 1종. **핵심 명사·원소보다 대기·반복·동시성 같은 "동작 관계"가 더 크게 소실된다**는 진단이 여기서 나왔다. 그래서 fixture JSON 일치가 아니라 사건·관계·안무 역할을 보는 의도 모델과 자동 채점기(`audit:sequence-intent`)를 만들어 기준선을 자동 91점·모드 일치 26/30으로 고정했다.

그 뒤 **프로덕션과 분리한 실험 Worker**에 후보 프롬프트를 순차 배포해 매번 실제 Gemini로 30종을 재호출했다. 후보 1~5는 각각 68·81·76·80·79점 — **전부 기준선 미달이라 스스로 전량 기각**하고 "자연어 규칙을 더 얹는 방식은 중단한다"며 접근을 바꿨다. 다시 세운 후보 55~58에서 6개 세트 105/105 정상 응답·자동 93~99점을 확보했고, 이 과정에서 *마지막 효과 뒤의 어색한 공백*이 판정이 아니라 **로컬 실행 타임라인**(마지막 단계를 항상 온전히 기다림) 때문임을 저장된 응답 8개로 분리해 진단했다.

최종 **#319**에서 판정 단계 계약의 `move`를 걷어내 일반 영창을 `form`/`wait`로 재구성하고, 제한을 푼 **필살영창**(4~8단계·병렬·피날레)을 게이지에 연결했다. **현재 배포된 프롬프트 `meaning-v2.31`이 이 결과다** — 일반 영창 최초 응답 12/12 유효·평균 1.472초·재요청 0, 회귀 88/88.

### 대표 기여 ② — 능동형 마나 C안

시전 경제 3개 후보 중 이도원이 플레이 가능한 프로토타입으로 만든 안이 팀 채택되어, **"적을 처치해 마나를 얻는다 = 영창하려면 싸워야 한다"**는 현재 코어 루프가 됐다. R2의 "현행 마나는 사실상 죽은 자원(3초 쿨다운이 버스트를 죽인다)" 진단이 실측으로 확인된 것이 채택의 발판이었다.

### 대표 기여 ① — 판정을 "측정 가능한 것"으로 만들었다 (#158 · #268)

화면에서 순식간에 지나가는 판정을 **로그만으로 재구성**할 수 있게 했다. 세션 ID와 절대시각을 공유하는 이벤트에 판정 출처(`gemini`/`cache`/`fallback`/`mock`)·지연·단일/시퀀스·단계 수·폴백 사유·실제 시퀀스 진입 여부를 남기고, 총괄 리뷰를 받아 런·방 경계와 Gemini upstream 상태(`http_502_upstream_429`)까지 보존했다 — **완주당 호출 수의 분모가 이때 생겼다.**

이 규율은 곧바로 값을 했다. 총괄이 "판정 품질 결함 7건"을 보고했을 때 R2는 **실 Gemini는 40/40 정확이며 문제 사례가 전부 Mock 폴백이었다고 반박했고**, 캐시를 지우고 출처를 다시 찍은 재현에서 총괄 측정이 폴백을 Gemini로 오인한 것으로 확인돼 프롬프트 수정 PR이 닫혔다. *"판정 측정은 반드시 출처를 기록하고 캐시를 지운 뒤"* 가 이후 팀 규칙이 됐다. 첫 실플레이 판독에서 Gemini 지연 p50 1,418ms·폴백 0, fixture 우회를 막은 재측정에서 timeout 폴백 21.1%를 잡아낸 것도 이 계기판 덕이다.

### 대표 기여 ② — 모델 별칭 드리프트 대응 (#107)

`-latest` 별칭이 2.5 → 3.1 → 3.5로 **말없이 갈아타고** 있었고 `gemini-2.5-flash-lite`는 이미 폐기(404)된 상태임을 확인해, `gemini-3.5-flash-lite` **명시 핀**으로 옮기고 프록시 레이트리밋을 Gemini 실제 한도(15 RPM)에 맞췄다. 부수 효과가 컸다 — 구 모델에서 7%였던 판정 폴백이 신모델 실측 **0/10**으로 사라져, 폴백 정책 게이트(#83)가 "현행 유지"로 닫혔다. 심사 기간에 판정 거동이 제멋대로 바뀌지 않는 것이 이 결정의 값이다.

### 대표 기여 ① — 실측으로 닫은 게이트

트랙 B 신규 기능의 컷/승격을 **회의가 아니라 근거로** 정했다. 7/28로 잡혀 있던 게이트 회의를 **닷새 앞당겨 7/23에 조기 확정**했는데, 4개 안건의 근거가 전부 실측으로 닫혔기 때문이다 — 소환 행동 DSL 수율 **20/20**(승격 조건 ≥70%), 판정 폴백 **0/10**(구 모델 7% 해소), 정령 투자 런의 오토/수동 화력 비중 **65.6%**(설계 상한 67%와 ±2% 일치). 근거를 문서로 남기고 *"이의 없으면 안건 없음"*으로 전파해, 회의 자체를 없앴다.

같은 원칙을 반대 방향으로도 적용했다. 제단 최상위 보상 후보였던 *파문*은 **동작 근거가 아니라 UI 상한(보상 카드 4장) 정책이 먼저 정해져야 한다**는 이유로 제출 범위에서 뺐고, 그 판단을 회귀로 고정해 되돌아오지 못하게 했다.

### 대표 기여 ② — 화면을 봐야만 아는 버그를 CI가 잡게 했다

회귀 **119종** 중 상당수는 순수 로직이 아니라 **씬 배선**을 지킨다. 시작점은 감사였다 — 당시 회귀 67종 중 맵 배선을 지키는 것이 **0종**이라, `refreshMinimap()` 호출을 지워도, 갈림길 한쪽의 `enterMapNode()`만 지워도 **CI가 전부 초록**이었다. 진행이 어긋나는 이런 버그는 실행해서 눈으로 봐야만 드러나고, 증상이 간헐적이라 가장 늦게 발견된다.

그래서 씬 소스를 문자열로 검사해 "이 배선이 사라지면 빨개지는" 회귀를 세웠고, **버그를 일부러 심어 회귀가 실제로 빨개지는지 확인하는 돌연변이 시험**으로 회귀 자체의 실효성을 검증했다. 실제로 지형 장벽의 밀어내기가 반대 방향으로 수백 px 튕기던 버그는 이 방식으로 잡았다 — 처음 세운 회귀가 너무 느슨해 176px 오차를 통과시켰고, 깊이별 정확 거리 검사로 조인 뒤에야 빨개졌다.

## 협업 방식

- **PR 기반 협업**: 브랜치 작업 → 리뷰 후 머지가 기본 경로 (머지된 PR 316건). 팀원 PR은 총괄이 검증된 리뷰(재현·반박 검증)를 달아 승인·변경요청으로 갈랐다
- **계약 우선(contract-first)**: 역할 경계의 인터페이스(판정 JSON 스키마, 보상 `RewardKind`, 맵 그래프 `MapGraph` 표면, 보스 기억 계약)를 **먼저 커밋해 고정**하고 그 위에서 병렬 작업 — 3인이 서로 다른 에이전트를 동시에 몰 수 있었던 핵심. 실제로 R1 그래프 구현이 계약 6메서드에 정확히 맞춰 도착해 씬 통합이 하루 안에 끝났다
- **회귀로 방어**: 순수 로직 + **씬 배선 검사**를 회귀 스크립트 119종으로 고정. 배선 유실은 화면을 봐야만 아는 종류의 버그라, 코드 문자열 검사로 CI가 잡게 했다. 돌연변이 시험(버그를 심고 회귀가 빨개지는지)으로 회귀 자체의 실효성도 검증
- **AI 사용 즉시 기록**: 작업 직후 [AI_USAGE_LOG.md](AI_USAGE_LOG.md)에 1줄씩 (누적 385건 — 제출물 ④의 원천 데이터)
- **인수인계 문서화**: 기계·AI 세션이 바뀌어도 이어갈 수 있도록 [TEAM_WORKFLOW.md](TEAM_WORKFLOW.md)에 페이즈 사이클·공통 규칙·인터페이스 계약을 고정

### 역할 간 인터페이스 계약

| 경계 | 계약 |
|---|---|
| R1 ↔ R2 | 판정 JSON 스키마(`SpellSpec`·`SpellJudgement` v2) — 변경 시 양측 합의 |
| R1 ↔ R3 | 보상 계약(`RewardKind`·`RunController` 이벤트), 맵 그래프 표면(`MapGraph` 6메서드 — R1 소유 순수 모델, R3 소비), 씬 전환 |
| R2 ↔ R3 | 영창 UX 타이밍(판정 대기 연출), 보스 대사 포맷, 시퀀스 `form`/`wait` 스키마 |

> 제출물 ①(빌드+소스)은 **전원 공동 책임** — 배포 파이프라인은 R3가 관리.
