# 영창 Judge 30종 정적 수동 평가

> 대상: `SEQUENCE_FIXTURE_ALIGNMENT_BASELINE.json`의 현행 Worker 응답  
> 기대 기준: `SEQUENCE_JUDGE_EXPECTATIONS.json`  
> 평가 범위: JSON에서 확인 가능한 의미 보존과 안무 구성  
> 평가 제외: 실제 렌더링의 타격감, 가독성, 속도감, 이펙트 품질

## 1. 이 평가의 위치

자동 점수는 원소·형태·행동·구조 같은 최소 계약 훼손을 찾는 하한선이다. 이 문서는 자동 점수로 판단하기 어려운 다음 항목을 사람이 정적으로 검토한다.

- 입력에서 기대되는 핵심 사건이 출력에 존재하는가
- 각 단계가 서로 다른 역할을 갖는가
- 단계 사이의 인과·전환·반복이 읽히는가
- `move`가 의미 있는 사건인가, 시퀀스를 만들기 위한 장식인가
- 정확한 legacy plan과 달라도 더 설득력 있는 해석인가

판정 의미:

| 판정 | 의미 |
|---|---|
| 통과 | 정적 계약과 안무 의도가 충분하다. 실제 장면 검증 대상으로 유지 |
| 수정 필요 | 핵심 의미 일부는 남지만 표현이 일반적이거나 안무 역할이 약하다 |
| 실패 | 입력의 필수 사건·관계가 사라졌거나 다른 일반 영창으로 축약됐다 |

이 판정은 최종 시각 평가가 아니다. `통과`도 실제 게임 장면에서 가독성과 재미를 확인해야 한다.

## 2. 전체 결과

| 결과 | 수 |
|---|---:|
| 통과 | 4 |
| 수정 필요 | 14 |
| 실패 | 12 |

구조적 편중:

- 시퀀스 출력 20종 중 **19종이 2단계**다.
- 시퀀스 출력 20종 중 **17종이 `move → form`** 골격이다.
- 따라서 자동 계약 점수 91점과 달리, 정적 안무 기준에서 바로 유지할 수 있는 결과는 4종뿐이다.

## 4. 프롬프트 7번 재작성에 반영할 실패 유형

### A. 시퀀스 형식 자체를 목표로 삼는 문제

복합적인 입력을 받으면 의미 관계를 설계하기보다 `move` 하나와 `form` 하나로 시퀀스 모양을 만든다. `move`는 이동이 입력의 핵심 사건일 때만 사용해야 한다.

### B. 명사를 속성·형태 하나로 축약하는 문제

`산 → earth wall`, `성역 → light wall`, `별 → light bolt`처럼 핵심 명사를 가장 가까운 enum 하나로 치환한다. 명사보다 동사와 관계를 먼저 추출해야 한다.

### C. 시간 관계의 손실

두 번의 박동, 동시 포화, 전개 후 폐막, 융합, 역류처럼 순서·동시성·반복·전환을 요구하는 입력에서 관계가 자주 사라진다.

### D. 복합 정체성의 단일 원소 평탄화

일식, 무지개, 팔원소처럼 복수 원소 자체가 정체성인 입력을 대표 원소 하나로 축약한다. 명시된 복수 원소와 대비 관계는 보존해야 한다.

### E. 지원 enum을 사용했다는 사실과 장면이 성립한다는 판단의 혼동

유효한 `form`, `move`, `element`를 출력해 validator를 통과해도, 사건 사이 인과가 없으면 만족스러운 안무가 아니다. 프롬프트는 각 단계의 존재 이유를 내부적으로 점검하도록 유도해야 한다.
